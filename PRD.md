# PRD: «Закупки. Понятно» — цифровой помощник по закупкам Самрук-Қазына

## 1. Проблема и контекст

Порядок осуществления закупок АО «Самрук-Қазына» и организаций группы (версия 2.16, ред. от 18.02.2026) — объёмный нормативный документ (~100 статей, 12 приложений). Большинство сотрудников, инициирующих закупку, не являются специалистами по закупочным процедурам и не должны изучать документ целиком, чтобы провести одну конкретную закупку.

**Проблема пользователя:** «Мне нужно что-то купить для компании — я не знаю, какой способ закупки применить, какие документы готовить и с чего начать».

## 2. Цель продукта

Дать любому сотруднику группы понятный, интерактивный путь от вопроса «что и как купить» до готового плана действий — без чтения нормативного документа целиком, но с точными ссылками на конкретные статьи Порядка.

**Продуктовая формула:** «Расскажи, что тебе нужно купить — мы подскажем, как правильно провести закупку».

## 3. Целевая аудитория

- Инициаторы закупок (любой сотрудник, впервые или регулярно проводящий закупку)
- Специалисты по закупкам
- Руководители, согласующие закупку
- Юристы и финансовые специалисты, работающие с договорами
- Новые сотрудники без опыта в закупочных процедурах

Продукт не предполагает знания пользователем юридической терминологии.

## 4. Ключевые сценарии использования

### 4.1 Мастер закупки
Пользователь вводит предмет закупки и проходит 8 вопросов (что закупаем → стоимость → особенности → основания для одного источника → наличие действующего договора → срочность → наличие в электронном магазине → приоритет отечественного производителя). На выходе — карточка с рекомендуемым способом закупки, обоснованием, условиями, документами, шагами, рисками и ссылкой на статью Порядка. Если данных недостаточно — система прямо говорит «нужно уточнить» вместо категоричного ответа.

### 4.2 Проведи меня по закупке
Визуальный маршрут из 9 этапов (Идея → Планирование → Выбор способа → Подготовка документации → Проведение закупки → Определение поставщика → Договор → Исполнение → Закрытие), с прогресс-баром. По каждому этапу — чек-лист, документы, действия пользователя, типичные ошибки, нормативное основание.

### 4.3 База знаний
17 тем Порядка простым языком, единая структура на каждую: что это / когда применяется / что нужно сделать / ограничения / пример / типичные ошибки / нормативное основание.

### 4.4 Умный поиск
Пользователь задаёт вопрос своими словами, получает краткий ответ и точную статью-основание. Поиск работает по curated Q&A-базе, без обращения к серверу.

### 4.5 Калькулятор способа закупки
Отдельный инструмент с теми же вводными, что и мастер, но в форме одной страницы с живым пересчётом результата — для тех, кто уже понимает свою закупку и хочет быстрый ответ.

### 4.6 Интерактивные чек-листы
4 чек-листа (перед публикацией закупки, перед заключением договора, перед изменением договора, перед закрытием договора) с отметкой пунктов и процентом готовности.

## 5. Функциональные требования

| # | Требование |
|---|---|
| F1 | Расчёт рекомендуемого способа закупки на основе суммы (в МРП текущего года), особенностей предмета закупки, оснований для одного источника, срочности, наличия в электронном магазине |
| F2 | Единая логика принятия решения используется и в мастере, и в калькуляторе |
| F3 | Явное указание «нужно уточнить» вместо ответа, когда введённых данных недостаточно |
| F4 | Каждая рекомендация и каждая тема базы знаний содержит ссылку на конкретную статью Порядка |
| F5 | Видимая дата актуальности нормативной базы на каждой странице |
| F6 | Чек-листы сохраняют прогресс в рамках сессии и показывают процент готовности |
| F7 | Поиск работает офлайн (без сервера), по ключевым словам |
| F8 | Интерфейс не требует знания юридической терминологии — формулировки на бытовом языке |

## 6. Нефункциональные требования

- **Актуальность:** нормативная база должна периодически обновляться; версия и дата редакции документа отображаются в шапке сайта.
- **Доступность:** адаптивная вёрстка (десктоп/планшет/мобильный).
- **Производительность:** статический сайт (HTML/CSS/JS), без сборки и серверной части — быстрая загрузка.
- **Скромность в выводах:** инструмент не выдаёт категоричный юридический вывод при недостатке данных (см. F3).

## 7. Вне рамок MVP

- Учётные записи пользователей и сохранение истории между сессиями
- Интеграция с реестром квалифицированных потенциальных поставщиков (Реестр КПП) и веб-порталом закупок
- Автоматическое обновление нормативной базы из внешнего источника
- Юридически обязывающие заключения (продукт — справочный, не заменяет службу закупок/комплаенс)

## 8. Метрики успеха

- Доля пользователей, доходящих до результата мастера закупки (завершение воронки из 8 шагов)
- Количество запросов в поиске без релевантного ответа (сигнал для расширения базы знаний)
- Обратная связь от службы закупок о снижении числа типовых ошибок (дробление закупок, неверный выбор способа, нарушение сроков)

## 9. Риски

- **Устаревание данных:** пороговые суммы зависят от МРП текущего года — требуют ежегодного обновления констант.
- **Излишнее доверие к рекомендации:** пользователь может воспринять справочный инструмент как окончательное решение — митигируется дисклеймером в подвале и формулировкой «нужно уточнить».
- **Неполнота базы знаний:** документ Порядка охватывает больше нюансов (ПКО, категорийные стратегии, региональные особенности), чем отражено в MVP.

## 10. Техническая реализация (справочно)

Статический одностраничный сайт: HTML + CSS + vanilla JS, без внешних зависимостей выполнения (кроме шрифта). Все данные (пороги, основания, темы базы знаний, маршрут, чек-листы, Q&A) — в JS-объектах внутри `index.html`, что упрощает публикацию (в т.ч. через GitHub Pages) и последующее редактирование содержимого без пересборки.
